The Unforgetting Machine

ChatGPT crossed one billion weekly users this week — a milestone that once seemed decades away. At the same time, a quietly remarkable paper arrived: a model that doesn't just access memories from outside itself, but carries them inside, the way a person does.

The one thing

OpenAI confirmed on August 6 that ChatGPT has reached one billion weekly active users — up from 900 million in February and achieved in under four years since launch. The milestone came seven months behind the company's own internal target, but still faster than any consumer internet product in history. It arrived alongside GPT-5.6 Sol, an upgraded tier for paid subscribers that OpenAI says cuts factual errors by up to 68%. At the same time, the free tier gained default access to GPT-5.6 Luna — the same model whose price was quietly cut 80%, to $0.20 per million input tokens, in the same week.

Paper, explained: Memory baked in, not bolted on

Metis: Memory Foundation Model · MemTensor & Renmin University of China · arXiv 2607.26760

This paper caught our eye because it asks a question most AI work quietly sidesteps: what if memory lived inside the model itself — the way it does in a human brain — rather than in a separate system bolted on from the outside?

The problem, and why it's hard

When you ask a language model something today, it starts fresh every single time. It carries things it learned during training — knowledge, language, reasoning patterns — but nothing from your previous conversations, unless those conversations are manually stuffed back into its context window before each new message. Two workarounds exist, and both have the same fundamental flaw.

The first is retrieval-augmented generation (RAG): search an external database for relevant snippets, paste them into the prompt, and let the model read them like a student cramming before a test. The second is an ever-larger context window: just send the whole conversation history every time. Both approaches treat memory as extra input — text added to the beginning of the prompt. This is slow (more text means more computation), expensive (costs scale with token count), and brittle: the model can lose track of older facts when the conversation grows long, and it can't combine stored knowledge in the same fluid way a person can.

The question Metis asks is whether memory can instead be native — a persistent internal state that the model updates automatically as it processes information, the way neurons update when a human remembers something. Building this into a standard transformer is genuinely hard. Transformers are trained to map a fixed input to an output. A changing hidden state that persists across separate conversation turns is not how they're designed, and making one stable enough to train required real architectural work.

How it works

Think of your own memory as a sketchpad you carry everywhere. When something important happens, you don't transcribe it word-for-word — you compress it into a brief, useful form and write a few notes. Later, when you need it, you consult the sketchpad directly rather than replaying the original event from scratch. The pad has finite space, so it drops redundant detail and keeps only the essential. Metis is this sketchpad, but woven into the layers of the transformer rather than sitting outside it.

The researchers insert new components into the transformer's existing layers, which they call Metis Blocks. Each block has two parts. The Local Memory Block maintains a compact numerical matrix — a continuously updated summary of everything the model has encountered in this session. The Hyper Memory Block, built on an architecture called a Gated Delta Network (GDN), decides what to write into that matrix and what to erase. When the model needs to answer a question, a memory attention step lets the current prompt consult whatever is stored in the matrix, blending retrieved memory with incoming text.

Crucially, all of this happens through a standard forward pass — the same computation the model runs to generate any token. There's no separate training step during deployment, no gradient descent at inference time, no retrieval query to a separate system. The weights that govern how memory is stored and retrieved were learned during training; after that they're frozen. Only the memory state keeps evolving during a conversation.

The researchers formalise four operations the model must learn: remember (store new information), forget (drop obsolete or incorrect facts), update (revise a stored belief when new evidence arrives), and reflect (draw inferences from stored knowledge without re-reading the original source). These aren't hand-coded rules. They're behaviours the model learns entirely from data — from synthetic training examples that demonstrate each operation.

What they actually did

MemTensor and Renmin University of China built Metis at three sizes — 4B, 9B, and 27B parameters — by inserting Metis Blocks into an existing Qwen3.5 transformer backbone. They trained on 406 million tokens of synthetically generated examples designed to exercise each of the four memory operations. Training ran on eight H100 GPUs. Because no suitable public memory benchmark existed, the researchers also built their own evaluation suite. Metis-27B scored 73.77% average across that test set. The baseline — identical Qwen3.5 without native memory, using context alone — scored 1.69%. Even the smallest Metis-4B model outperformed a 72B baseline model on these memory tasks.

What they found

The gap between 73.77% and 1.69% is not close. It's a category difference — like comparing someone who has studied a subject to someone handed a textbook seconds before an exam and asked to answer from scratch. The researchers found the expected pattern: larger Metis models consistently outperformed smaller ones. The hardest operation across all three sizes was reflect — drawing a fresh inference from stored knowledge — which makes intuitive sense: combining memory to form a new conclusion is more demanding than just retrieving a stored fact. Importantly, because all memory updates happen through a forward pass rather than gradient computation, adding native memory to a model doesn't meaningfully slow down inference. The memory state stays compact — fixed-size, regardless of how long a conversation runs.

The catch

Metis is a prototype, and its evaluation has real constraints. The benchmark the team used is one they built themselves from synthetic data, which means it tests exactly what the model was trained to do. We don't yet know how native memory performs on tasks from outside this controlled setting — and we don't know whether inserting Metis Blocks hurts general capabilities like coding or reasoning (the paper doesn't test these). The training set of 406 million tokens is small by frontier standards. Perhaps most importantly, the paper's comparison is against Qwen3.5 without any memory at all — not against a strong RAG baseline or a well-tuned long-context system. The honest question — "is this better than the best external memory approaches in real applications?" — remains open.

If you remember one thing: The gap between AI with memory woven in and AI relying on context alone — 73.77% versus 1.69% on the same tasks — is so large it suggests that external memory is a workaround, not a real solution, and that the field has been treating a structural problem as a retrieval problem.

Why it matters

This week pulled in two directions at once. Outward: a billion people using the same system every week is a social fact with few precedents — it means that for a large fraction of the world, a single AI is now embedded in daily decisions about work, health, study, and communication. Inward: papers like Metis are trying to make that system fundamentally more capable of being yours — of building and maintaining a model of you and your context across time, rather than treating every conversation as a blank page. The gap between those two things — colossal reach, zero memory — is what most AI products are quietly struggling to close. Metis doesn't close it yet, but it is the most direct attempt so far to ask the right question.

Decoder

Word of the day
Native memory
Memory that lives inside the model itself rather than in a separate database. Instead of fetching notes and reading them at the start of each conversation, the model carries a compressed internal record that updates automatically — like the difference between looking up a fact in a filing cabinet and simply knowing it.
MoE (Mixture of Experts)
A model architecture where only part of the network activates for any given input. Qwen3.8-Max has 2.4 trillion parameters total but uses only 95 billion at a time — keeping a massive model efficient by routing each query to the most relevant specialists.
Context window
The maximum amount of text a model can "see" at once, measured in tokens (roughly three-quarters of a word each). Beyond this limit, the model starts forgetting the beginning of a conversation — like a screen that scrolls old text off the top.
RAG (Retrieval-Augmented Generation)
Giving a model access to external documents by searching for relevant chunks and pasting them into the prompt before each query. Fast and effective, but every query pays the cost of extra tokens.
VLA (Vision-Language-Action)
A model that takes in images and text and outputs actions — for example, translating camera feeds into steering decisions. NVIDIA's Alpamayo 2 Super uses this to go from omnidirectional cameras on a vehicle to a driving command.
Inference
Running an already-trained model to generate output. Training is where a model learns; inference is where it works. Most of the electricity (and cost) in deploying AI products comes from inference, not training.
