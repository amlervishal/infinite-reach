Above the Podium

An Nvidia system entered the world's most prestigious programming competition this summer, followed every rule the human contestants followed, and came out first. It arrived the same week as a paper showing how the training data for the next generation of coding agents is already being written by the current one.

The one thing

Nvidia's Nemotron-3-Ultra-CC scored 535.4 out of 600 at the International Olympiad in Informatics (IOI) 2026 — ahead of the top human contestant's 498.27 — running under the same time limits, submission rules, and internet restrictions as the students in the room. The system is a competition-specific build: a 550-billion-parameter mixture-of-experts model, with 55 billion parameters active on any given response, tuned specifically for contest programming. Nvidia published the result in a new arXiv preprint this week; it hasn't been independently replicated, and the team hasn't claimed the system would do as well on general-purpose coding. But the margin is real, and it is the first time a machine has beaten every human at IOI under actual competition conditions.

Paper, explained: Turning old AI work logs into new training gyms

Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments · Jie Wu, Zhenru Zhang, Beichen Zhang, et al. (Alibaba Qwen Team / Tsinghua University) · arXiv 2609.04148

Every time an AI coding agent solves a problem — navigating files, running commands, editing code — it leaves behind a detailed log: every step, every command, every tool call. These logs are called trajectories. Most teams treat them as read-only history. This paper, from Alibaba's Qwen group and Tsinghua University, asks what happens if you treat them as blueprints for a live training gym instead.

The problem, and why it's hard

To improve a coding agent through what researchers call post-training, you need verifiable environments: real programming setups where the agent can attempt something, receive genuine feedback (does the code run? does the test pass?), and try a different approach. Building those environments by hand is expensive and slow — you need repositories, tasks, and ground-truth solutions that are clean enough for systematic training. Meanwhile, AI coding agents are being deployed everywhere and leaving behind millions of trajectory logs. Those logs contain implicit information about real programming environments — the file structures, the commands that worked, the errors that didn't — but a trajectory on its own is frozen. It is a recording of someone else working, not a workspace you can practice in.

Before this paper, the standard use of a trajectory was to extract a single training example from it: here is the task, here is how the agent solved it, now learn to imitate that. One trajectory, one example, one use. The mismatch is significant: environments are the scarce resource, and trajectories are abundant. The question is how to bridge them.

How it works

Terminal-Universe's central insight is that every trajectory carries enough information to reconstruct the environment it came from. Think of each trajectory as a detailed film of a chef cooking in a particular kitchen: every tool they reached for, every ingredient they used, every correction they made. The traditional approach uses that film as a lesson — watch and imitate. Terminal-Universe uses the film to rebuild the kitchen, so that new AI systems can walk in, practice the same recipe or try different ones, and receive genuine feedback about whether the dish turned out.

In practice, the framework does three things. First, it parses each trajectory to recover the state of the file system and command environment at each step — effectively reverse-engineering the workspace behind the recording. Second, it wraps that recovered state in a live, sandboxed Docker container: a self-contained environment that can be started, queried, and discarded at will. Third, it "probes" that environment with a range of new questions: What if the task had been to fix this bug instead of add that feature? What if the directory structure were slightly different? What if the target file were renamed? Each probe that yields a verifiable answer — one where you can run code and check the result — becomes a new training task, with ground truth built in. One trajectory can spawn dozens of tasks. A library of trajectories can produce tens of thousands of environments.

What they actually did

The team applied Terminal-Universe to publicly available terminal agent trajectory datasets — sessions where AI agents had worked through real programming tasks on the command line. From that raw material, the framework produced 37,300 task-sufficient environments: environments where at least one new verifiable task could be extracted. They then used this corpus to fine-tune Qwen3.5-27B, a 27-billion-parameter language model from Alibaba's own Qwen family. Crucially, the fine-tuning was standard supervised fine-tuning rather than the more complex and compute-intensive reinforcement learning — a deliberate choice to isolate the effect of better training data rather than a fancier training algorithm.

What they found

The fine-tuned model improved single-round performance on Terminal-Bench 2.1 by 11.9 points and multi-round performance on EvoCode-Bench v2 (a benchmark that tests agents across several back-and-forth steps on the same problem) by 13.8 points. Both benchmarks test agents on realistic terminal-based programming tasks — the kind of work a developer does at the command line, not the kind of tidy puzzle that appears in coding contests. The gains are meaningful: on crowded leaderboards where frontier models typically separate by two to five points, an 11–14 point jump from data alone is notable. The team also found that multi-round performance improved more than single-round — suggesting that the environments are teaching the model to recover from mistakes and course-correct, not just to execute correctly on the first attempt.

The catch

The quality of the generated environments depends entirely on the quality of the source trajectories. The paper uses publicly available data, which skews toward the kinds of tasks developers demonstrate publicly — tidy, well-defined, successful sessions. Real production software is messier, more ambiguous, and often fails in ways that aren't well-represented in public trajectory datasets. Additionally, the "task-sufficient" threshold means only that at least one new task could be extracted; it says nothing about how challenging or diverse those tasks are. An environment that generates ten variants of "add a unit test to this function" is adding less than an environment that explores genuinely different programming scenarios. The paper doesn't yet address how to filter or diversify the probe-generated tasks.

If you remember one thing: Recycling AI coding sessions into live training environments — rather than frozen examples — can add 11–14 benchmark points to a model with no new human-curated data, just better use of the logs already piling up.

Why it matters

The IOI result and the Terminal-Universe paper arrived in the same week, and they are telling the same underlying story from two different angles. At the frontier, AI coding systems have reached and passed the human ceiling on one of the most structured and demanding programming tests that exists — under actual competition conditions, not selected benchmarks. Meanwhile, researchers are demonstrating that the logs those systems generate can become the training material for the next generation, at almost no marginal cost. These two things together suggest that coding-agent capability may now be self-reinforcing in a meaningful way: every deployment generates trajectory data, and that data can compound into better models without requiring human labelers or new task designs. Whether the IOI win translates to everyday software engineering is genuinely uncertain — the system was purpose-built for contests, not for the underspecified, dependency-tangled work most professional coding involves. But the direction of travel is clear, and the pace appears to be accelerating rather than levelling off.

Decoder

Word of the day
Trajectory
In machine learning, a trajectory is a step-by-step record of everything an AI agent did during a task — every command typed, every file opened, every error hit and recovered from. Think of it as a detailed receipt for an entire work session. Abundant and cheap to collect; the hard part is knowing what to do with it afterwards.
Mixture of Experts (MoE)
An architecture where a large model is divided into specialist sub-networks. For any given input, only a fraction of those sub-networks activates — so a "770B-parameter" model might actually do its work with 49B active parameters, keeping costs manageable.
Post-training
Adjustments made to a model after the main large-scale training phase — fine-tuning it on specific tasks, incorporating feedback, or reinforcing desired behaviours. The difference between going to school and then doing an internship to specialise.
Supervised fine-tuning (SFT)
A type of post-training where you show the model many labeled examples (question → ideal answer) and train it to match them. Simpler and cheaper than reinforcement learning, but it requires a curated dataset. Terminal-Universe is valuable partly because it provides that dataset automatically.
Benchmark
A standardised test for AI models designed to allow fair comparison across systems. Like a standardised exam for schools — useful for tracking progress, but never a complete picture of real-world performance.
Inference
The act of a trained model generating an output — when it runs to answer a question or write code, as opposed to when it is being trained. "Inference costs" are what you pay every time the model is actually used by someone.
