What You Build Around It

Anthropic just became the first frontier AI lab to post a quarterly operating profit — two years ahead of its own schedule. At almost the same moment, a paper arrived showing that the biggest leap in AI agent performance this year didn't come from a better model. It came from better plumbing.

The one thing

Anthropic's preliminary revenue for Q2 2026 came in at more than $11.5 billion — up from $787 million in the same quarter of last year, and from $4.73 billion in Q1 2026. The company also posted its first-ever positive adjusted operating income: roughly $559 million. Compute costs, as a share of revenue, fell from 71 cents per dollar to 56 cents in a single quarter, suggesting the efficiency curve is finally bending in Anthropic's favour. The company is now reportedly targeting a $2 trillion IPO valuation. Twelve months ago, that number would have seemed like science fiction.

Paper, explained: the better cage

StateM: Reaching 95.3% Raw Accuracy, or a $15 Frontier Run, on Terminal-Bench 2.1 via Harness Scaling · Ziheng Qin et al. · arXiv 2608.15089

Almost every conversation about making AI agents smarter assumes you need a smarter model. This paper politely disagrees. It shows that wrapping an existing model in a better execution structure lifts it from 83% accuracy to 95% — outscoring a more expensive model — without changing a single parameter in the model itself.

The problem, and why it's hard

AI agents that do real computer work — writing code, running shell commands, fixing bugs — operate in long, sequential chains. A task might take dozens of steps. The fundamental problem is that language models have a limited attention window: they can only "see" so much text at once. As a session goes on, early decisions fall out of view. The agent forgets what it already tried, repeats mistakes, loses track of which step it's on. The usual answers are to give the model a bigger context window, or to write longer, more detailed prompts. Neither solves the real issue: the model's working memory is doing structural bookkeeping it was never designed to do.

How it works

Think of StateM like a surgeon's pre-op checklist. The checklist doesn't make the surgeon more talented — it makes the surgical team more reliable. It enforces a shared reality: everyone knows exactly where they are in the procedure, what has been verified, and what can't be skipped. StateM does the same thing for AI agents. It divides every task into five named phases — Plan, Run, Review, Repair, Done — and enforces a hard rule: you cannot leave a phase until a set of "gates" passes. A gate can be a shell command that has to succeed, an explicit checklist the agent must complete, or a sub-model that reviews the output before clearance to proceed.

Crucially, none of this state lives inside the model's context window. It lives in a durable file on disk — outside the model entirely. If the agent crashes, gets interrupted, or runs out of context mid-task, the runbook picks up from the last verified checkpoint, like a save point in a video game. The model at any given moment sees only the context relevant to its current phase. It doesn't have to hold the entire task history in memory because the harness holds it instead. And if the Review phase flags a problem, the agent transitions to Repair, fixes what went wrong, and loops back to Run — not to the beginning of the task.

What they actually did

The authors tested two models — GPT-5.6 Sol and DeepSeek-V4-Flash — against Terminal-Bench 2.1, a benchmark of 89 practical computer-use tasks (coding, file system operations, shell work) run over 445 trials. They measured what happened when each model ran with and without the StateM harness, and compared both to the published reference baseline and to GPT-5.6 Sol Ultra — a larger, slower, more expensive model.

What they found

With StateM, GPT-5.6 Sol reached 95.28% raw accuracy (424 of 445 trials). The reference baseline — the same model, standard prompting, no harness — scored 83.1%. GPT-5.6 Sol Ultra, the pricier model that was previously the top score, sat at 91.9%. In other words, StateM on a cheaper model outscored the more expensive one by more than three percentage points. DeepSeek-V4-Flash with StateM reached 88.76% — above the unassisted Ultra. The authors also claim that because StateM's gates prune redundant work, a full Terminal-Bench run costs approximately $15.

The failure modes were instructive. Most remaining failures occurred when the Review phase couldn't catch a subtle semantic error (as opposed to a command failure), and when tasks required long chains of interdependent shell operations that the current phase structure didn't fully decompose. The system is better at knowing it has failed than at knowing it is about to fail.

The catch

Terminal-Bench 2.1 tests a specific and relatively structured class of agent tasks — computer use in a terminal. Real-world tasks are messier. It's unclear how much of the gain survives when tasks don't decompose neatly into five phases, or when the task type changes entirely. The authors also tested a single harness design; how sensitive the 12-point improvement is to the specific gate definitions, phase boundaries, and runbook format is an open question. And the paper itself uses frontier models for its gates, so the $15 figure is only meaningful if your base model is already in that tier.

If you remember one thing: A checklist that lives outside the model — with hard gates between steps — can be worth more than upgrading to a more expensive model.

Why it matters

Three signals this week point the same direction. Anthropic's first profit shows that a frontier AI company can now sustain itself on real revenue — not just the next investment round. The A2A and MCP protocols uniting under neutral governance shows the agent communication layer is mature enough to need a standards body. And the StateM paper shows something more subtle: the biggest performance gains right now are hiding in the structure around a model, not inside it. We've spent years comparing model scores as if the model were the whole product. The lesson accumulating across these stories is that the environment — the harness, the protocol, the company — is increasingly where the competitive advantage lives. The model is necessary but no longer sufficient.

Decoder

Word of the day
Harness
The code, structure, and rules built around a model that shape how it behaves. Think of the difference between a surgeon and a surgical system: the same skill produces different results depending on the checklists, protocols, and teamwork surrounding it. StateM is a harness. So is MCP. The model is the engine; the harness is the car.
Terminal-Bench
A benchmark that tests AI agents on real terminal tasks — writing code, managing files, running shell commands — to measure practical computer-use ability.
Durable state
Information about a task's progress saved outside the model (to a file or database) so it survives crashes, interruptions, or context resets. The agent resumes from the last checkpoint instead of starting over.
Operating profit
Revenue minus the direct costs of running a business (salaries, compute, offices), before accounting for debt interest or taxes. A positive number means the business earns more than it spends to operate — often the first milestone after years of investment-funded losses.
MCP / A2A
Two complementary agent protocols. MCP (Model Context Protocol, from Anthropic) defines how an agent connects to tools and data sources. A2A (Agent-to-Agent, from Google) defines how agents communicate with each other. Both are now governed by the Agentic AI Foundation.
AAIF
Agentic AI Foundation — a Linux Foundation body formed to provide neutral governance for the protocols that underpin multi-agent AI systems. MCP joined first; A2A joined on August 20, 2026.
