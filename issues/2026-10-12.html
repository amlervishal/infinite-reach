Between the Theorems

This week, twenty-five of the world's most decorated mathematicians said that mass-producing proofs is a form of soil depletion. And a paper posted three days ago asks a strangely similar question about what AI agents lose when they summarise their own memories.

The one thing

On October 6, OpenAI published 722 model-generated mathematical manuscripts in a single batch to GitHub — results derived by its internal models across a broad sweep of open problems. The release drew a sharp public response from Terence Tao and twenty-four other Fields Medal laureates, who argued that mathematics builds its real value not from results alone but from the surrounding territory: the methodology, the dead ends, the derivative questions that open up once a problem is cracked. By releasing hundreds of proofs in bulk, without the context that normally surrounds mathematical discovery, they said OpenAI is making the field "less fertile" — generating harvest without leaving seeds. The debate cuts to a question that will outlast this particular batch: when an AI produces a result, what does it mean to publish that result responsibly?

Paper, explained: The AI agent that remembers what prose can't say

REMORY: Learning Residual Memory for Context Compaction · Hanchen Xia, Baoyou Chen, Yutang Ge, et al. · arXiv:2610.11287, submitted October 8, 2026

Every AI agent that handles a long task is quietly fighting a space problem. REMORY, posted three days ago by a team including researchers from eight institutions, offers the cleanest solution yet — and the core idea turns out to be simpler than the terminology around it.

The problem, and why it's hard

An AI agent works inside a "context window" — think of it as the agent's short-term memory, a notepad that holds the whole conversation, all the tool results, and everything the model needs to keep track of. For a brief exchange, this is fine. But agents running real tasks — browsing the web for an hour, writing and testing code across dozens of iterations, calling external APIs in multi-step pipelines — fill that notepad quickly. When it runs out of room, something has to go.

The standard fix is context compaction: ask the model to summarise its own history into a short block of text, throw away the rest, and carry on from the summary. This is already how systems like Claude Code handle long sessions. The problem is that prose summaries are lossy in a particular way. They capture facts — "the user wants a parser that handles nested JSON" — but lose texture: the exact phrasing of past outputs, the structure of what was tried, the subtle pattern of which approaches already failed. These nuances live not in English but in the model's mathematical interior, and no summary sentence can fully recover them. The visible symptom in real deployments: agents with compacted contexts repeat tool calls they already made, loop through approaches they already ruled out, and lose track of partial progress.

How it works

Imagine a skilled research assistant summarising a dense 300-page dossier before a meeting. They produce two pages of bullet points — but then, in the margin, they scribble five handwritten notes: "Section 4 is what the boss always asks about first." "The red-flag metric is buried on p. 212." The bullet points cover the facts; the margin notes encode a kind of judgment that no summary sentence could carry.

REMORY works exactly this way. When the context window fills up, a conventional text summary is produced — just as before. But then a second, smaller network (about 1.2 to 1.9 billion parameters, far smaller than the main model) reads that text summary and generates a bounded set of "soft memory tokens." These aren't words. They're vectors — numerical entries in the model's mathematical language — that sit alongside the text summary and fill in what prose couldn't say. The frozen main model sees both: the text and the soft tokens together, as though a margin note had been stitched into the fabric of the prompt.

The "residual" in the name is the precise technical term for this. In deep learning, a residual connection is a shortcut that adds back signal lost during compression — a way of saying: here is what the lossy step dropped, put it back. REMORY does the same thing along the sequence of inputs: the soft tokens carry the residual between what the full context contained and what the text summary preserved.

Crucially, the main model is never changed. Its weights stay frozen. Only the small memory network is trained — it learns to generate the right soft tokens by comparing, during training, what the model produces with the full context versus what it produces with only a text summary. The gap between those two outputs is exactly what the memory tokens are trained to close. This means REMORY can in principle be trained on top of any frozen base model, without touching the model itself.

What they actually did

The team trained two memory networks — 1.9B and 1.24B parameters — and paired them with two frozen base models: Qwen3.8-27B and GLM-5.3-Flash. They tested across three benchmarks. SummHay asks agents to answer questions by attributing answers to specific passages in a long document — a task that demands precise recall of where information came from, not just what happened. BrowseComp tests a web-browsing agent on multi-step research tasks across the open web. Terminal-Bench 2.1 tests a code agent working in a live terminal across multi-turn debugging sessions where context from earlier turns directly affects what to try next.

What they found

On SummHay, REMORY approaches full-context performance while using only 5.2% of the input positions — meaning 94.8% of the original history is discarded and replaced by soft tokens. On the two agentic benchmarks, both Qwen3.8-27B and GLM-5.3-Flash showed consistent improvements over text-only compaction: fewer repeated tool calls and fewer tool errors across the evaluation runs. The authors describe this as the agent retaining a better operational feel for what it has already tried — the soft tokens appear to prevent the looping behaviour that is the most visible failure mode of compacted contexts.

The paper reports comparison trends rather than absolute accuracy numbers for each individual task — a caveat worth noting. And because the soft tokens live in one specific model's embedding space, each base model needs its own trained memory network. The team releases two networks (one for each base model they tested); anyone wanting to use REMORY with a different LLM would need to train their own on comparable data.

The catch

REMORY doesn't eliminate the context problem — it makes compaction less destructive. The history is still being discarded; you are recovering more of the signal, not all of it. For tasks that require very precise recall of specific outputs far back in the session — a long coding project where the exact error message from forty turns ago matters — it isn't yet established that 5.2% is enough. The paper is also three days old and the published benchmarks have not been independently replicated.

If you remember one thing: Text summaries lose the math; REMORY trains a small side-network to generate margin notes in the model's native numerical language, cutting the active history to 5.2% of positions while keeping most of what actually matters.

Why it matters

The two main stories this week rhyme at the root. Terence Tao's objection to OpenAI's math batch and the REMORY paper are both about the same thing: the parts of knowledge that resist compression. A text summary of a long agent session loses nuance; a batch of 722 model-generated proofs, published without the mathematical context that normally surrounds discovery, loses culture. In both cases, the easy version of the information — the result, the summary — strips away something that may matter as much as the output itself.

For practitioners, REMORY is immediately useful: a 1.2-billion-parameter add-on that makes context compaction substantially less destructive. For everyone else, the mathematics debate is a preview of a question that will sharpen as AI systems produce more: are we building systems that generate results, or systems that build knowledge? The difference is what lives between the theorems.

Decoder

Word of the day
Context window
The model's working memory — everything it can "see" at once. Think of a desk with a fixed surface area: more papers mean some slide off the edge. When a conversation grows long enough, old material falls out of view and the model can't access it.
Context compaction
Squeezing a long conversation into a shorter form the model can still work from — usually by having it write a text summary of its own history, then discarding the original. Fast and cheap, but lossy.
Soft tokens
Entries in a model's vocabulary that aren't words — they're trained numerical vectors that carry meaning the model can read, but a human can't. Mathematical shorthand the network invented, not English.
Residual connection
A shortcut in a neural network that adds back signal lost during a compression step. REMORY borrows the idea: the soft tokens carry the "residual" — whatever the text summary couldn't preserve.
Embedding space
The mathematical layer where every word and idea in a language model lives as a list of numbers. Two ideas that are conceptually close sit close together numerically. Soft tokens live here too — points the network placed there during training.
Agent harness
The software scaffolding around an AI model that decides which tools it can use, in what order, and how to manage the context window — the wrapper that turns a raw language model into a task-completing agent.
