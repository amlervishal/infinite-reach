At the Wheel

The White House announced an AI Force and rejected calls for any development slowdown — the same week a zero-click security flaw let attackers quietly hijack AI coding tools, and a new paper measured just how much the wrapper around a model shapes what it achieves.

The one thing

On Saturday, President Trump announced plans to create an “AI Force” modelled on the Space Force and to appoint an AI czar — and explicitly rejected the September 12 letter signed by Sam Altman, Dario Amodei, and Elon Musk calling for government pacing mechanisms. “We will not in any way hinder or stifle the Growth of this incredible Industry,” he wrote on Truth Social. The announcement named neither the czar’s duties nor the force’s mission nor any timeline. What it established clearly is that the administration’s current position is maximum acceleration — and that the proposal from three of the world’s most powerful AI executives for any kind of government-enforced speed limit is, as far as Washington is presently concerned, dead.

Paper, explained: Does the wrapper around an AI agent matter as much as the model?

How Do Agent Harnesses Create Value? Planning Information and Release Control in Stateful LLM Agents · Yukun Zhang, Kemu Xu, Yishen Chen · arXiv 2609.20474

Every AI agent lives inside a harness — the code layer that hands it a goal, tools, and sometimes a plan before it starts. Builders have long suspected the harness matters. This paper actually measured it. The results have a direct bearing on how engineering teams should spend their time.

The problem, and why it’s hard

When an agent completes a multi-step task — processing a return, modifying a flight booking — it’s almost impossible to know what drove that success. Was it the model’s underlying reasoning? The instructions it received before it started? The way its output was checked at the end? Researchers and engineers have intuited that “better scaffolding helps,” but intuition isn’t a measurement. The field has been building increasingly elaborate harnesses — pre-written workflows, automated verifiers, memory systems — without a clean answer to the basic question: which part is actually carrying the weight?

The challenge is that you can’t simply compare “harness on” versus “harness off,” because a harness does many things simultaneously. You need a way to isolate one component while holding everything else constant — and that is harder than it sounds when the system you’re studying is a language model reading free text.

How it works

The researchers’ key move is borrowed from pharmaceutical trials: the placebo condition. They compared two kinds of guidance given to an agent before each task:

The Fixed plan is a task-specific, pre-written workflow — step-by-step guidance tuned to the actual task type, such as how to handle a partial-order return in a retail system. This is the real intervention, the thing a careful engineer would write.

The Sham plan is the same amount of text, but scrambled. The words are real; the length is identical; but the sentences have been shuffled into nonsense. The agent still reads this text before it starts — it just contains no useful signal.

Think of it like a musician who receives either a correct lead sheet or a correct-looking lead sheet with the measures in the wrong order. The paper, the format, the length: identical. The meaning: gone. If the agent does better with the Fixed plan than the Sham, that proves it is the planning content that matters — not some artifact of merely having text in the harness at all.

They also tested a second component: a verifier. Rather than trusting the agent to self-report whether it finished correctly, this is a read-only automated checker that looks at the terminal output and makes its own call on whether the task was actually completed.

What they actually did

The experiment used τ²-bench, a benchmark of realistic customer-service tasks across two domains: Retail (product returns, order changes) and Airline (booking modifications, refunds). They ran 265 matched task cells — paired comparisons where the same underlying task was given to an agent with a Fixed plan and then a Sham plan — keeping task complexity constant to enable a direct apples-to-apples comparison. The verifier was evaluated on the Retail domain.

What they found

The Fixed plan beats the Sham plan by 7.17 percentage points in oracle-verified success — the fraction of tasks the agent completes correctly (90% confidence interval: 1.15 to 13.36 points). The gains are uneven: harder, more complex tasks benefit more than simple ones. For tasks where an agent could probably muddle through anyway, Fixed and Sham look roughly alike. For multi-step tasks with conditional logic and edge cases, the gap widens considerably.

The verifier tells a sharper story. It correctly rejects 61% of episodes where the agent claimed success but actually failed — failures that a system without a verifier would have reported as completed. The cost of that catching is a false-negative rate of 17%: real successes the verifier wrongly flags as failures. The per-episode cost of running it: under one cent.

Whether you prioritise the planning gain or the verifier gain depends on what kind of mistake is more expensive in your context. In low-stakes settings — exploratory queries, casual drafting — getting more tasks right (the planning gain) tends to dominate. In high-liability settings — financial transactions, health bookings, anything where a wrong confirmation causes real harm — catching false completions (the verifier’s role) becomes more valuable than any gain in raw success rate.

The catch

The study covers two task domains, both in the customer-service family. Whether these results hold in coding tasks, scientific research, or open-ended creative work is not established. The 7.17-point improvement is statistically meaningful but modest — it won’t rescue a weak model or a badly designed system. The Sham condition is also not the same as having no plan at all; agents given truly empty context might behave differently. And the verifier is domain-specific, not a general-purpose quality gate that can be dropped unchanged into any workflow.

If you remember one thing: Good planning guidance reliably improves an agent’s success by about 7 points — not because models are bad at reasoning, but because knowing the shape of a task before it starts is genuinely valuable information, and that’s as true for a language model as it is for a person.

Why it matters

This week’s stories share a thread: the question of who holds the wheel. Trump said the government will not constrain AI development, installing an unnamed czar and creating a new force without specifying either’s role. Plugin4Shell showed that four widely-trusted AI coding tools shared a hidden assumption that let attackers silently take control of a developer’s machine. And the agent harness paper showed that the decisions made before a model starts running — the instructions handed to it, the checks placed on its output — matter more than many builders appreciate. As AI agents earn more trust and take on more autonomous work, what’s inside the harness becomes as consequential as what’s inside the model. That’s a design problem, a security problem, and now, apparently, a political one too.

Decoder

Word of the day
Harness
The code layer that wraps around an AI model to give it a goal, tools, memory, and a plan before it starts. The model is the engine; the harness is the cockpit, the seat belt, and the route planner. This week’s top paper measured how much the harness itself — not the engine — determines how far you get.
τ²-bench
A benchmark that tests AI agents on realistic multi-step tasks — customer-service returns, airline booking changes — designed to be close enough to real work to show where a model and its scaffolding succeed or fail under pressure.
Zero-click vulnerability
A security flaw that an attacker can exploit without you doing anything. No link to click, no file to open — the attack fires when software performs a routine action it normally trusts.
Pacing proposal
A suggestion — here, from Altman, Amodei, and Musk — that AI developers accept pre-set limits on training runs or capability jumps, coordinated with governments, to create space for safety reviews before each new model ships.
RLCD
Reinforcement Learning from Calibrated Decisions. A training method that rewards a model for emitting structured choices (yes/no, which category) rather than open text — keeping outputs short, fast, and easy to verify.
Recursive self-improvement
The theoretical ability for an AI to improve its own training process or architecture, so that each generation produces a better version of itself without humans redesigning it from scratch.
